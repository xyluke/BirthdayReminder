# 生日提醒 · 原理说明（学习文档）

这份文档用大白话讲清楚这个 App 是怎么工作的。读完你会明白：为什么敲几个命令就能变成手机上能装的 App，农历生日是怎么算出来的，数据存在哪里，以及出了问题该往哪看。

我不会只讲结论，每个环节都会指到真实文件，你可以照着文件边看边理解。

## 1. 这个 App 到底是什么

一句话：**它本质是一个网站（网页应用），只是被做成可以像 App 一样用。**

它是"B端一个网页、手机上两种打开方式"：

```
本项目 (D:\motheRemind)
   │
   ├── 网页部分（Vue3+Vite 写的，所有功能都在这里）
   │
   ├── 方式① iPhone：当成 PWA，Safari「添加到主屏幕」
   │            → 浏览器开一个网页，只是全屏、有图标、能离线
   │
   └── 方式② Android：打包成 APK 安装
              → 安卓系统开一个「壳」（WebView），壳里塞进同一个网页
```

**核心洞察**：所有逻辑（记录生日、农历换算、倒计时）只写了一遍、在网页里；iPhone 和安卓共享同一份。不同的只是怎么把它"呈现"出来。

- 浏览器直接打开 → 网页
- 主屏幕全屏 → PWA
- 安卓 App → APK（一个包了一层原生壳的网页）

这就叫**跨平台**：写一次，到处跑。

## 3. 网页部分：从代码到浏览器怎么跑

你敲 `npm run dev` 时发生了什么：

```
你在浏览器打开 http://localhost:5173
        │
        ▼
Vite 开发服务器 读取 index.html
        │  (src/main.ts 是入口)
        ▼
index.html 里挂着 vue 入口 → 创建 App.vue 这个根组件
        │  App.vue 里：
        │    · 顶部导航栏（van-nav-bar，来自 Vant）
        │    · 中间生日列表（遍历数据 → 一行一行渲染）
        │    · 右下角 "+" 按钮 → 弹出添加表单（BirthdayForm.vue）
        ▼
数据从 localStorage 读出来 → 界面显示
点了"保存" → 数据写回 localStorage → 界面自动更新
```

**关键概念：响应式（reactive）**
Vue 的核心魔法。你可以打开 `src/composables/useBirthdays.ts` 看：

```ts
const birthdays = ref<Birthday[]>(loadBirthdays())   // 一个"会通知"的变量
```

`ref` 包起来的变量，一旦你改它，凡是界面上用了它的地方会自动重新渲染。所以你不需要写"改完数据还要手动刷新界面"这种代码，框架帮你干了。

> 类比：Excel 里改了单元格，公式自动重算。Vue 的 ref 就是这个机制。

## 4. 农历生日是怎么算出来的（最容易懵的部分）

### 4.1 为什么需要专门的库

公历（新历）一年固定 12 个月，有规律。农历有**闰月**（有的年份多一个月）、月份有**大月小月**（30 或 29 天）之分，规则复杂到没法手写，所以直接用别人写好的库 `lunar-typescript`。它不是算出来的，你甚至可以理解成它是**内置了一本超大万年历**，你问它"某年某月某日农历对应公历哪天"，它查表告诉你。

### 4.2 闰月用负数表示

打开 `src/utils/lunar.ts`。里面最关键的一行逻辑是：

```ts
const m = b.leap && leapMonth === b.month ? -b.month : b.month
```

翻译：**如果这条生日是闰月、而且今年恰好有这个闰月 → 月份取负数（负数 = 闰月）**。
这个负数约定是库的规则：`Lunar.fromYmd(2025, -6, 1)` 表示 2025年**闰六月初一**；`Lunar.fromYmd(2025, 6, 1)` 是普通六月初一。

你想想这个点巧在哪：一个 4 月生日，不用负数的话，"普通四月"和"闰四月"就没法区分；用正负号区分，一个变量就同时表达了"几月"和"是不是闰月"，干净利落。

### 4.3 怎么算"下一个生日是哪天"

核心函数 `nextOccurrence`（同样在 lunar.ts）。分两种：

**公历生日**（超简单）：
```ts
const candidate = new Date(y, b.month - 1, b.day)
return candidate >= today ? candidate : new Date(y + 1, b.month - 1, b.day)
```
今年这天还没过 → 用它；过了 → 用明年。就这两行。

**农历生日**（要逐年试）：
```
对 今年、明年（最多后年）逐年尝试：
  1. 查今年有没有闰月、闰的是几月      → leapMonth = getLeapMonth()
  2. 决定今年用正数还是负数月份         → 见 4.2
  3. 查这个月和今年有多少天（29/30）    → getDayCount()
     · 如果生日是"三十"，这月只有 29 天 → 退到廿九（防错位）
  4. 把农历转成公历日期                 → getSolar()
  5. 如果这个公历日期 >= 今天 → 就是它了，返回
```

为什么"逐年试"？因为闰月不是每年都有（比如闰四月的年份可能在 5 年后才轮到），所以要把今年、明年一个个试过去，找到第一个落在今天或之后的日期。

### 4.4 一个完整例子

你的朋友生日是 **农历闰四月初三**（`month=4, day=3, leap=true`）：

| 年份 | 有闰四月吗？ | 用哪个月 | 结果 |
|---|---|---|---|
| 2026 | 无 | 四月 | 四月初三→ 若已过，跳过 |
| 2027 | 无 | 四月 | 四月初三 → 取这个 |

如果 2027 年的四月初三公历是 5月8日，且今天在它之前，那就返回 2027-5-8。
规则是：**闰月生日，闰月不出现的年份就按普通月过**——这符合国内习俗，也写进了表单里的小字提示。

### 4.5 列表怎么排序

`useBirthdays.ts` 里有个 `computed`，它对每条数据调用上面的 `nextOccurrence`，算出"还剩几天"，然后按天数从小到大排。所以**最靠近生日的排最上面**，今天过生日的显示"今天"并高亮。排序在第 N 天跨年时也会自动重新算，因为每次渲染都用"现在"为基准。

## 5. 数据存在哪 & 为什么备份重要

数据存在浏览器的 **localStorage** 里（`src/utils/storage.ts`），一个 key 对应一份 JSON 数组。

关键点——**localStorage 是"按域名隔离"的**：
- 在 `http://192.168.x.x:5173` 存的 → 只有在这个地址能读到
- 装 APK 后 → 数据存进安卓 App 自己的 WebView 空间里（跟着 App 走）

所以：
- iPhone 上从"测试地址"换到"正式部署的域名" → 数据不会自己跟过来
- 这就是为什么做了"导出/导入备份"，换环境时把 JSON 迁过去（`src/utils/backup.ts`）

> localStorage 本质就是一个键值对数据库，存的是字符串，数据量小、按 key 读写。想成浏览器自带的一个小记事本就行。

## 6. "可安装"/"离线" 怎么来的（PWA）

PWA 有两大法宝，都在 `vite.config.ts` 的 `VitePWA({...})` 里配置：

### 6.1 manifest（配置文件）—— 让它能被"装上"
安装到主屏幕时，系统要读一份自我介绍文件 `manifest.webmanifest`，里面写了：
- 应用名叫什么（生日提醒）、图标是哪些（`pwa-192.png` 等）、主题色（`#ee6a63`）
- 打开后要不要全屏（`"display": "standalone"`）

系统看到这份文件 → 就知道"这是一个可以安装的应用"，于是 Safari/Chrome 出现"添加到主屏幕/安装应用"。

### 6.2 Service Worker（后台脚本）—— 让它能离线
你第一次打开网页时，浏览器会额外启动一个后台脚本 **Service Worker**（由 `vite-plugin-pwa` 构建时自动生成 `sw.js`）。它的工作是**把你访问过的所有文件缓存到本地**。

下次打开断网了：
```
用户请求 → Service Worker 拦截 → 从本地缓存返回 → 照样能打开
```

`vite-plugin-pwa` 用的 generateSW 模式，就是构建时扫描你打包出的文件，自动写出一份"把哪些文件缓存起来"的清单，省得你手写。

> 类比：第一次打开时"把整个网页下载到手机内存"，之后离线也能用。

### 6.3 为什么 APK 里把这部分关掉了
打开 `src/main.ts`：

```ts
if (!Capacitor.isNativePlatform()) {
  registerSW({ immediate: true })
}
```

意思是：**在 APK（原生环境）里不注册 Service Worker**。为什么？
因为 APK 里的网页文件是"打包死的"，你安装新版本 → 新文件替换旧文件。如果 Service Worker 还留着旧缓存，可能升级后还显示旧页面，反而坑。而 APK 本身不需要"离线缓存"——文件就在手机里，本来就能离线。

如果正常运行不是 APK（网页/PWA），就注册 SW 获得离线能力。一行 `if` 区分两种场景。

## 7. 从网页到 APK：Capacitor 在干嘛

### 7.1 什么是 WebView
安卓手机里有个内核叫 **WebView**，本质是一个"能开网页的组件"。很多 App 里面嵌了它，就是为了让一小块界面用网页技术写。

**Capacitor** 做的事就一句话：
> 你写好了一个网页（`dist/` 里的静态文件），我把它全部塞进一个安卓工程，用系统 WebView 打开它。

这就是为什么：
- 你的 APK 只有 4.3MB —— 里面主要就是那几 MB 网页文件和一小段壳代码
- 你的 App 完全离线可用 —— 网页文件就装在本地，WebView 直接读本地文件，不需要网

### 7.2 打包流程
```
npm run build                    # ① 用 Vite 把 src/ 打包成 dist/（纯静态文件：html/js/css）
npx cap sync android             # ② 把 dist/ 拷贝进 android/app/src/main/assets/public/
./gradlew assembleDebug          # ③ 用 Gradle 把壳+网页+资源 编译打包成 APK
```

`capacitor.config.ts` 里配置：
```ts
appId: 'com.moheremind.app',     // 应用唯一标识（类似身份证号）
appName: '生日提醒',              // 显示在手机上的名字
webDir: 'dist'                   // 告诉 Capacitor："要打包的网页在 dist 目录"
```

我的 `npm run cap:sync` 命令就是把①②绑在一起，方便你一条命令搞定。

> 类比：Capacitor 是集装箱航运公司，你的网页是货物，安卓壳是集装箱。发货（build）→ 装柜（sync）→ 运输（gradle）→ 收货（安装到手机）。

## 8. 安卓构建工具链（之前卡住的根源）

构建 APK 时，下面这一串工具按顺序配合：

```
Java (JBR/JDK) ──> 运行 Gradle
     Gradle ──────> 读取 build.gradle，询问 Android 插件(AGP) 怎么打
    AGP ──────────> 用 Android SDK 里的编译工具 + android-36 平台 把代码编译打包
    结果 ─────────> app-debug.apk
```

每个角色：

| 工具 | 是什么 | 你家（本项目）的地位 |
|---|---|---|
| **JDK (Java)** | 一个编程语言运行时 + 编译器 | 一切安卓构建都要它先跑起来 |
| **Gradle** | 通用"自动化构建"工具 | 总指挥，负责下载依赖、执行任务 |
| **AGP**（Android Gradle Plugin） | Gradle 的一个插件 | 教 Gradle 怎么"打安卓包" |
| **Android SDK** | 官方的编译工具 + 各版本系统库 | 里面的 `android-36` 是"编译用的系统版本" |

**之前为什么卡住**（你现在能对上号了）：

1. SDK 缺 `android-36`（项目要求 compileSdk=36），你的 Studio 只下到了别的版本 → 编译时找不到要用的系统库
2. Gradle 分发包在国内下载慢 → 一直转圈 = "卡住"
3. **最大的坑**：你的 Android Studio 自带的是 Java 25，而项目用的 Gradle 8.14.3 只支持最高 Java 24 —— 两者不兼容。所以我装了一个 JDK 21，构建时指定 `JAVA_HOME` 指向它（`D:\1Soft\jdk\jdk-21.0.12.1+1`），绕开了这个坑

这也是为什么那些"下载地址"要换成国内镜像：dl.google.com 和 services.gradle.org 在国内不稳定，腾讯/阿里/清华的镜像站把它们的东西拷了一份，访问快得多。

## 9. 一次完整的端到端走查（把上面全部串起来）

> 场景：朋友过农历生日，今天是 2026-10-22，你要添加一条"农历八月初十"的生日。

```
① 你点 "+" → BirthdayForm.vue 弹窗
② 选「农历」，月份列选"八月"，日期列选"初十"
③ 点保存 → 表单组装出 { type:'lunar', month:8, day:10, leap:false },
           传给 useBirthdays().add() → 存进 localStorage → 界面更新
④ 列表用 nextOccurrence() 算这个生日下一次的公历日期:
     2026年八月初十 的公历（农历八月初十 ≈ 今年9月前后）已经过了
     → 试 2027年八月初十 → 得到公历日期 → 返回它
⑤ 算出"还剩 N 天" → 插到列表对应位置
⑥ 你点右上角"⋯"→ 导出备份 → 生成 birthday-backup-*.json 文件，存好以防万一
   ------------------------------------------------------------
   以上全在"网页"里发生，iPhone 和 Android 用的是同一套代码
   ------------------------------------------------------------
⑦ 想做成安卓 App → npm run build → cap sync → gradlew assembleDebug
   → app-debug.apk → 传到手机安装 → 手机 WebView 打开同一个界面
```

从此以后，那个朋友每年生日，打开 App 第一个就是它，显示"还有 N 天"，到了当天显示醒目的"今天"。

## 11. 推荐的自学路径

如果想深入，按这个顺序看，每层都基于上一层：

1. **先把 Vue 3 官方教程过一遍**（vuejs.org 有中文）——理解 `ref`、`computed`、组件、事件
2. 对着本项目**把 App.vue 和 BirthdayForm.vue 读一遍**，每个标签查 Vant 文档
3. 建一个 5 分钟的小实验：改一处样式（比如把主题色改成蓝色），看界面跟着变，建立"改哪→变哪"的直觉
4. 再去看 `lunar.ts`，先在 console 里手动调 `Lunar.fromYmd` 多试几个日期，验证万年历直觉
5. **最后**再碰构建部分（Gradle/Capacitor）——那些是"工程化"的事，先把页面逻辑玩熟

前端最好的学法：**别怕改坏，反正有 localStorage 和数据在某处，改崩了大不了重新来。** 多改、多跑、多看图变化。
